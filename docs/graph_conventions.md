# 이 폴더에 그래프를 그릴 때 지킬 것

2026-07-30 작성. `1_command_tracking_v28.png` 외 3장을 보고, 실제로 어긋난 것만 적었다.
일반적인 시각화 조언이 아니라 **이 폴더에서 이미 틀린 것들**의 목록이다.

참조 구현은 같은 폴더의 `plot_gait_compare.py`, `plot_periodicity.py`다.
v12~v25 그래프 30장이 저 두 스크립트에서 나왔다. 새로 짜기 전에 먼저 읽을 것.

---

## 0. 그리기 전에

**이 폴더를 먼저 `ls` 하라.** 사용자는 새 그래프를 **기존 30장과 나란히 놓고**
본다. 혼자 예쁜 그림보다 v25와 겹쳐 읽히는 그림이 낫다.

파일명은 기존 규약을 따른다: `v{번호}_{한글설명}.png`
(`v25_6방향_속도추종.png`, `v24_최종_주기성.png`)
`1_command_tracking_v28.png`처럼 숫자 접두사 + 영문으로 새 규약을 만들면
정렬이 깨지고 같은 지표의 버전 간 비교가 눈으로 안 된다.

## 1. 축 범위 — 가장 크게 틀린 것

`1_command_tracking_v28.png`의 6개 패널 y축이 전부 다르다:
정지 −0.8~0.2 / 좌 −0.25~1.0 / 우 −1.0~0.2 / 회전 −1~3.

두 가지가 동시에 망가진다.

- **비교가 불가능해진다.** 6방향을 한 장에 놓는 이유는 서로 비교하려는 것인데,
  축이 다르면 눈으로 비교할 수 없다. 같은 물리량(m/s)을 그리는 패널은
  `sharey=True`로 묶어라. 회전만 rad/s이므로 그것만 분리한다.
- **신호가 납작해진다.** 정지 패널의 실제 데이터는 0 근처 ±0.05인데 축이
  −0.8까지 늘어나 평평한 선으로 보인다. 축을 늘린 주범은 데이터가 아니라
  **10~90 백분위 띠의 극단값**이다.

띠가 축을 지배하면 `ax.set_ylim()`을 데이터(굵은 선) 기준으로 직접 잡고,
띠는 잘리게 두고 캡션에 "띠 일부가 축 밖으로 잘림"이라고 적어라.
축을 늘려 신호를 죽이는 것보다 낫다.

## 2. 좌우 대응 관절의 부호가 반대다

`3_joint_tracking_v28.png`: left knee가 −90~−110°인데 right knee는 +100~+120°.
ankle도 좌 +40~+60 / 우 −30~−60으로 뒤집혀 있다.

이 상태로는 **좌우 비대칭을 볼 수 없다.** 그런데 좌우 비대칭은 지금 이 프로젝트의
미해결 과제다 (횡 이탈 좌 247mm vs 우 143mm, `docs/handoff/README.md`).
보려고 그린 것을 못 보게 그린 셈이다.

좌우를 비교하는 그래프에서는 한쪽 부호를 뒤집어 겹쳐라. **단, 뒤집기 전에
`source/open_duck_mini_isaaclab/joint_order.py`와 URDF에서 부호 규약을 실제로
확인하라** — 추측으로 뒤집으면 없는 비대칭을 만들어낸다. 뒤집었으면 캡션에
"오른쪽 관절 부호 반전"이라고 반드시 적는다.

## 3. 레퍼런스를 빼지 마라

`2_gait_diagram_v28.png`에는 정책의 접지 패턴만 있고 레퍼런스가 없다.

이 프로젝트는 **모방 학습**이다. 레퍼런스 없는 그래프는 "정책이 무엇을 하는가"만
말하고 "맞게 하는가"는 말하지 않는다. `plot_gait_compare.py`가 매 그림에서
파선으로 레퍼런스를 겹치는 이유다. 접지 다이어그램이면 레퍼런스 접지를 반투명
막대로 뒤에 깔거나 위아래 두 줄로 나란히 놓아라.

기존 규약: **실선 = 정책 / 파선 = 레퍼런스**, 파선은 짝이 되는 실선과
**같은 색**에 `alpha=0.6`. 색으로 관절을, 선종류로 정책/레퍼런스를 구분한다.

## 4. 숫자를 적어라

잘하고 있다 — 유지할 것. `오차 0.032`, `관절 오차 6.0°`, `21 mm`처럼 제목이나
패널 안에 값을 박는다. 사용자는 그래프를 모바일로도 보고, 모양만으로는 개선
여부를 판정하지 않는다.

RMS는 rad과 도(°)를 함께 적는다 (`0.104 rad (6.0°)`). 진폭은 비율까지
(`정책 0.42 vs 레퍼런스 0.68 rad/s (비 0.62)`).

## 5. 글자가 겹치면 그래프가 아니다

`2_gait_diagram_v28.png`의 부제가 "왼발" 행 라벨과 겹쳐 `색발 접지 (정착)`처럼
읽힌다. y축 라벨 `레퍼런스 위상 [스텝]`도 회전 상태로 잘렸다.

- `constrained_layout=True` 또는 `tight_layout(rect=...)`으로 자리를 확보한다.
- 부제를 여러 줄 쓸 거면 `fig.subplots_adjust(top=...)`로 위쪽을 비운다.
- 저장한 뒤 **직접 열어서 보라.** 겹침은 코드로는 안 보이고 그림에만 보인다.

## 6. 캡션 문자열에 튜플이 새어나왔다

`1_command_tracking_v28.png`의 세 번째 줄이 이렇게 렌더링됐다:

    ('굵은 선 = 4개 환경 평균 · … · 회색 구간 = 과도구간(오차 계산에서 제외)',)

괄호와 쉼표가 보이는 것은 **문자열 끝에 쉼표가 붙어 튜플이 된 것**을 그대로
그린 결과다.

    cap = ("굵은 선 = …",)     # ← 튜플
    cap = "굵은 선 = …"        # ← 이렇게

파이썬이 에러를 내지 않으므로 그림을 열어보지 않으면 끝까지 모른다. 5번과 같은
이유로, 저장 후 열어볼 것.

## 7. 한글/영문을 섞지 마라

`3_joint_tracking_v28.png`은 제목·축·오차가 한글인데 관절명만
`left hip yaw`다. `4_path_drift_v28.png`의 축 라벨은
`path frame 대비 횡방향 이탈`이다.

기준: **본문은 한글, 고유명사만 영문.** 코드 심볼(`joint_pos`, `lin_vel_xy`),
정착된 용어(`path frame`, `PPO`, `gamma`)는 영문 그대로 두고, 나머지는 한글로
옮긴다. 관절명은 `왼 무릎`, `오른 고관절 pitch`처럼 축 이름만 영문으로 남긴다.

## 8. 한글 폰트 (이 PC 기준)

이 PC에는 `NanumGothic`이 설치돼 있고 matplotlib이 인식한다. 확인된 이름:
`NanumGothic`, `NanumBarunGothic`, `NanumSquare`, `NanumMyeongjo`.

`plot_gait_compare.py`의 서두를 그대로 재사용하라:

```python
matplotlib.use("Agg")
for _f in ("AppleGothic", "Apple SD Gothic Neo", "NanumGothic"):
    try:
        matplotlib.font_manager.findfont(_f, fallback_to_default=False)
        plt.rcParams["font.family"] = _f
        break
    except Exception:
        continue
plt.rcParams["axes.unicode_minus"] = False
```

`axes.unicode_minus = False`가 없으면 음수 부호가 유니코드 −(U+2212)로 나가
폰트에 글리프가 없을 때 두부(□)가 된다. 이 프로젝트는 음수 축이 많다
(후진 −0.15, 관절각 −110°) — 빼먹으면 바로 드러난다.

## 9. 과도구간을 버려라

`WARM = 100` 스텝(약 2초)은 스폰 직후 자세를 잡는 구간이라 오차 계산에서
제외한다. v28 그래프가 회색으로 표시하고 제외한 것은 맞다 — 유지.

다만 **회색 구간까지 y축 범위에 넣지 마라.** 1번에서 정지 패널 축이 −0.8까지
늘어난 것의 일부가 이 구간 때문이다. 버릴 구간이면 축 계산에서도 버린다.
