# 액션 저역통과 필터: 떨림 억제와 학습 안정성

**Open Duck Mini V2 / Isaac Lab RL** · 2026-08-09 · 박수호

---

## 요약

학습된 정책이 **심하게 떨리는** 문제가 있었습니다. 액션에 1차 저역통과(LP) 필터를
거는 것이 해법인데, **이것을 배포 단계에만 붙일지 학습 환경에 넣을지**가 갈림길
이었습니다.

두 경우를 다 재봤습니다.

| | 떨림 | 명령 추종 |
|---|---|---|
| 배포에만 필터 (학습은 무필터) | 감소 | **단조롭게 악화** (+2% ~ +26%) |
| 학습에 필터 포함 | 감소 | 오히려 **학습이 더 빠르고 안정적** |

**결론: 필터는 학습 환경에 넣어야 합니다.** 배포에만 붙이면 정책이 겪어본 적 없는
위상 지연이 생기고, 이는 줄이려던 sim2real 격차를 스스로 만드는 셈입니다.

⚠️ 현재 검증 학습(v36)은 **3000 iteration 중 159**까지만 진행됐습니다. 아래
초반 수치는 확정이 아닙니다.

---

## 1. 문제 — 정책이 떨린다

Isaac Sim 재생(조이스틱 조종)에서 몸통이 눈에 띄게 떨렸습니다. 정량화하면:

| 조건 | 몸통 각속도 RMS | 관절 속도 RMS |
|---|---:|---:|
| 정지 | 0.1819 | 0.582 |
| 전진 (0.15 m/s) | 1.2254 | 5.037 |

(v35 정책, iter 2999, 32 env × 200 스텝, 외란 끔)

기존 구동 제한은 이 떨림을 못 막습니다. 목표각 변화율 제한
(`max_motor_velocity 4.82 rad/s × ctrl_dt 0.02 s = 0.0964 rad/step`)이 걸려
있지만, **그 한계 안에서 매 스텝 부호가 뒤집히는 진동은 그대로 통과**합니다.

> 참고: 아직 실기 배포 전이며, 위 관찰은 전부 시뮬레이션 재생 기준입니다.

---

## 2. 필터 — 무엇을 하는 것인가

액션에 1차 EMA(지수이동평균)를 겁니다.

```
a_f[t] = α · a_f[t-1] + (1-α) · a[t]
목표각  = default_joint_pos + a_f[t] · 0.25
```

시간축에서는 **스무딩**, 주파수축에서는 **1차 IIR 저역통과**입니다. 같은 것을 두
가지로 본 것입니다. brick-wall 차단이 아니라 −20 dB/decade로 완만히 감쇠하며,
**위상 지연**이 따라옵니다 (군지연 = α/(1−α) 샘플).

제어 50 Hz, 보행 주기 0.54 s (1.85 Hz) 기준:

| α | −3 dB 차단 | 군지연 |
|---:|---:|---:|
| 0.3 | 11.0 Hz | 8.6 ms |
| 0.5 | 5.8 Hz | 20 ms |
| 0.7 | 2.9 Hz | 46.7 ms |
| 0.8 | 1.8 Hz | 80 ms |

α = 0.8은 차단이 **보행 주파수보다 낮아져** 보행 자체를 깎기 시작합니다.

필터는 액션 쪽에 겁니다. 그래야 고관절 클램프와 속도 제한이 **필터 뒤에** 걸립
니다 — 순서를 바꾸면 필터 출력이 안전 한계를 다시 넘길 수 있습니다.

---

## 3. 실험 A — 학습된 정책에 사후로 필터 적용

v35 정책(무필터 학습)을 그대로 두고 추론 시에만 α를 바꿔가며 측정했습니다.

**정지**

| α | 몸통 각속도 | 정지 속력 오차 |
|---:|---:|---:|
| 0.0 | 0.1819 | 0.0148 |
| 0.5 | 0.1022 (−44%) | 0.0096 |
| 0.8 | 0.0585 (−68%) | 0.0056 |

**전진 (0.15 m/s)**

| α | 몸통 각속도 | 추종 오차 |
|---:|---:|---:|
| 0.0 | 1.2254 | 0.0766 |
| 0.5 | 1.0499 (−14%) | 0.0783 (+2%) |
| 0.7 | 0.9589 (−22%) | 0.0964 (**+26%**) |
| 0.8 | 0.9828 (−20%) | 0.1223 (**+60%**) |

넘어짐은 전 구간 0%.

**관찰 두 가지**

1. **정지는 대가가 없습니다.** α를 올릴수록 떨림도 줄고 정지 속력 오차도 같이
   줄어듭니다 (0.0148 → 0.0056).
2. **보행은 추종이 단조롭게 나빠집니다.** 그리고 α = 0.8에서는 떨림 감소마저
   뒤집힙니다(−22% → −20%) — 위상 지연이 보행 자체를 흔들기 시작한 지점입니다.

보행에서 추종이 나빠지는 것이 핵심입니다. **정책의 피드백 루프는 지연 0인 구동을
전제로 학습됐는데, 추론 시에만 20~47 ms 지연을 끼워 넣으면 정책이 보상할 방법이
없습니다.** 이것은 필터의 결함이 아니라 학습/배포 불일치의 대가입니다.

---

## 4. 실험 B — 필터를 학습 환경에 넣기

필터를 **플랜트의 일부**로 만들면 정책이 지연을 미리 보상하는 것을 배울 수
있습니다. α = 0.5(실험 A의 무릎점)로 학습을 다시 돌렸습니다.

동일 iteration 비교 (v35 = 무필터, v36 = 필터 포함):

| iter 100 | v35 | v36 | |
|---|---:|---:|---|
| imitation 리워드 | 0.170 | **0.188** | +10.7% |
| tracking_lin_vel | 0.0743 | **0.0882** | +18.7% |
| 평균 에피소드 길이 | 350.1 | **464.1** | **+32.6%** |
| 평균 총 리워드 | 127.0 | **184.9** | +45.6% |

**에피소드 길이가 가장 크게 올랐습니다(+32.6%).** 구동이 부드러워져 덜 넘어지고,
그 결과 유용한 상태에서 온폴리시 데이터를 더 많이 모아 학습이 빨라지는 것으로
해석됩니다.

> **에피소드 길이 착시가 아님을 확인했습니다.** `alive` 항이 두 런 모두 모든
> iteration에서 정확히 0.0600으로 동일합니다. alive는 스텝당 상수이므로, 만약
> 로그가 에피소드 합이라면 길이에 비례해 커져야 합니다. 상수라는 것은 지표가
> **스텝당으로 정규화**돼 있다는 뜻이고, 따라서 imitation +10.7%는 실제 스텝당
> 개선입니다.

## 5. 한계와 남은 검증

정직하게 적어 둡니다.

- **iter 159 / 3000 (5%)입니다.** 이 프로젝트의 학습 곡선은 단조롭지 않습니다 —
  이전 실험(v33n)은 iter 1400 이후에 11.7%가 더 올랐고 중간에 순위가 뒤집혔습니다.
  초반 학습 속도가 최종 성능을 보장하지 않습니다.
- **v36은 두 가지를 동시에 바꿨습니다** (필터 + 정지 좌우대칭 벌점). 다만 대칭
  항의 크기가 imitation의 약 1/600(−0.0005 vs 0.188)이라 에피소드 32% 증가를
  설명할 수 없고, 필터가 주 원인으로 보입니다. 두 항은 읽는 지표가 달라
  (대칭 = 관절각 어긋남, 필터 = 몸통 각속도 RMS) 학습 종료 후 분리 측정할
  예정입니다.
- **실기 검증 전입니다.** 실기 통신이 현재 10.8 Hz로, 정책이 학습된 50 Hz의
  1/5입니다. 이 격차를 먼저 해소해야 필터 효과를 실기에서 확인할 수 있습니다.
  (`latency_timer` 조정 + Dynamixel 통신속도 57600 → 1 Mbps)

## 6. 여쭙고 싶은 것

**실제 액추에이터의 대역폭과 내부 필터**에 대해 조언을 구하고 싶습니다.

지금 보는 떨림이 시뮬레이션 고유의 것인지, 실기에서도 나타날 것인지가
갈립니다. Dynamixel XM430-W350의 내부 위치 제어 루프가 이미 저역통과 역할을
한다면, 소프트웨어 필터는 중복이거나 과할 수 있습니다.

또한 저희 IMU 노이즈 모델은 **균일 백색잡음**뿐입니다. 실기에서 실제로 문제되는
것은 보행 진동에 의한 **에일리어싱과 바이어스 드리프트**일 텐데, 이를 시뮬레이션
에 어떻게 반영하는 것이 적절한지도 조언을 구하고 싶습니다.

(참고로 현재 학습 노이즈는 실제 센서보다 훨씬 큽니다 — 자이로 기준 학습
±0.1 rad/s(RMS 3.3 °/s) vs BNO055 실제 ~0.1 °/s RMS로 약 30배 여유. 백색잡음
측면에서는 IMU가 병목이 아닙니다.)

## 부록 — 재현 방법

```bash
# 사후 필터 스윕 (학습된 정책에 추론 시에만 적용)
scripts/diag/smooth_sweep.py --task <task> --checkpoint <pt>

# 재생에서 눈으로 확인
odm play v35 --smooth 0.6 --joystick

# 필터를 학습에 포함 (cfg.action_lowpass_alpha)
odm train v36 3000 4096
```

(`_pre_physics_step`의 액션 저역통과), 계수는 `joystick_env_cfg.py`의
`action_lowpass_alpha` (기본 0 = 꺼짐).
