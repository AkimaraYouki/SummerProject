# 실기가 심의 42 % 토크로 돌고 있었다 — 그리고 goto_ready 의 2배 오류

2026-08-12. 계기: "왼무릎이 보행 중 목표보다 22~32도 더 접힌 채 끌려다니고,
앞으로 꼬구라진다." 하드웨어 시험은 두 번 다 통과해서 (주파수 응답 이득
0.95~1.00 / 좌우차 2 % 이내, 손으로 몸통 들고 보행하면 정상 추종) 모터
자체는 무죄로 판명된 상태였다. 남은 후보가 서보 **설정** 이었다.

`scripts/hw/dump_ctrl_table.py` 로 14축 EEPROM+RAM 을 처음 전부 덤프했다.

## 1. 서보 설정은 무죄 — 좌우 완전 동일

| 항목 | 값 (다리 10축 전부 동일) |
|---|---|
| Position P / I / D Gain | 800 / 0 / 4700 |
| Velocity P / I Gain | 100 / 1920 |
| Feedforward 1st / 2nd | 0 / 0 |
| Drive Mode | 0 (정방향, 시간기반 프로파일 꺼짐) |
| Operating Mode | 5 (전류기반 위치제어) |
| Homing Offset | 0 |
| Min / Max Position Limit | 0 / 4095 (EEPROM 클램프 없음) |
| Profile Velocity / Acceleration | 0 / 0 (제한 없음) |
| PWM Limit | 885 (100 %) |
| Shutdown | 52 = 과열+전기충격+과부하 |
| Return Delay Time | 250 (= 500 us) |

**좌우로 다른 설정값은 하나도 없다.** 유일한 차이는 펌웨어 버전 (44 / 48 /
49 / 50 이 섞여 있다) 인데 무릎 두 축은 그마저 둘 다 44 다. 왼무릎 처짐의
원인은 서보 설정이 아니다.

## 2. Goal Current 350 — 심이 가정한 값의 절반

덤프에서 **Current Limit = 350 틱 = 0.9415 A** 가 나왔다. `rl_walk.py
--current` 기본값이 350 이었다.

`robot_cfg.py` 의 토크 모델은 ROBOTIS 성능그래프에서 뽑은 τ = 1.96·(I − 0.27):

| | 전류 | 관절 토크 |
|---|---|---|
| 심이 전제한 값 (`XM430_CONT_TORQUE_700`) | 1.883 A (700 틱) | **3.16 N·m** |
| 실기 실제 (v41~v46 전 기간) | 0.9415 A (350 틱) | **1.32 N·m** |

**실기는 심이 허용한 토크의 42 % 로 돌고 있었다.** v41 이후 모든 정책
(v41·v42·v43·v44·v46) 이 `effort_limit: 3.16` 으로 학습됐다 — 정책은 무릎에
3.16 N·m 를 쓸 수 있다고 배웠는데 실기는 1.32 N·m 에서 잘렸다. 체중을 받는
순간 무릎이 밀려 내려가고 앞으로 무너지는 게 정확히 이 증상이다.

상수 이름 자체가 `XM430_CONT_**700**` 인데도 못 잡은 이유: 두 숫자가 서로
다른 파일 (`robot_cfg.py` 와 `rl_walk.py`) 에 살았고, `robot_cfg.py` 의
주석은 "실기 `rustypot_hwi.py` 의 current_limit 700 틱" 이라고 **사실과
다르게** 적혀 있었다 (실제 기본값은 350). `rl_walk.py` 독스트링에는
"다리가 실제 보행 부하를 못 버티고 멈추면(주저앉으면) --current 를 올릴 것"
이라고 적혀 있었는데, 정확히 그 증상이 났는데도 아무도 올리지 않았다.

### 고친 것

* `rl_walk.py --current` 기본값 350 → **700**.
* `export_onnx.py` 가 `params/env.yaml` 에서 다리 `effort_limit` 을 뽑아
  `policy.meta.json` 에 싣는다 (ImplicitActuator 는 `effort_limit_sim`,
  DCMotor 는 `effort_limit`. v40 이전 = 4.1, v41 이후 = 3.16).
* `rl_walk.py` 가 시작할 때 `--current` 를 **토크로 환산해서** 심의
  `effort_limit` 과 나란히 찍고, 90 % 미만이면 경고한다. 암페어만 찍던 게
  두 값을 대조하지 못한 직접 원인이었다.
* `robot_cfg.py` 주석에서 틀린 서술을 고치고, 이게 심이 실기에 요구하는
  **계약** 임을 명시.

### 대가

700 틱 = 1.88 A 는 스톨 전류 2.3 A 의 82 %. 연속으로 물리면 발열과 Overload
래치가 온다 (v42 에서 겪었다). 매 스텝 temp/hw_error 를 찍으므로 60 °C 를
넘으면 멈출 것.

## 3. goto_ready 가 목표각의 절반까지만 갔다

같은 조사에서 별개의 버그가 나왔다. 젯슨의 `goto_ready.py` 만

    TICK_RAD = 4.0 * math.pi / 4096.0      # 틀림

를 들고 있었다. XM430 은 4096 틱이 1 회전이므로 `2.0*pi/4096` 이 맞다.
같은 상수를 가진 다른 네 파일 (`rustypot_hwi` / `dxl_bridge` / `joint_cal` /
`play_ref_gait`) 은 전부 맞았다 — **표를 복제한 대가다.**

효과: 모든 목표각이 중심에서 절반으로 줄었다. v46 READY 의 무릎 −76.7° 를
명령하면 실제로는 −38.3° 에서 멈춘다 (437 틱 차이).

그 상태로 `rl_walk` 를 켜면 램프인(기본 3 초) 이 나머지 38° 를 메우면서
지면에 선 로봇을 4 cm 강제로 주저앉힌다. 순간 충격은 아니지만 (한 스텝
낙하가 아니다) 시작 자세로서는 불안정하다.

여기에 더해 `goto_ready` 의 하드코딩 READY 표는 2026-08-08 자라 v46 과
최대 25.6° 어긋나 있었다:

| 관절 | 하드코딩 | v46 READY | 차이 |
|---|---|---|---|
| left_knee | −102.28° | −76.72° | +25.56° |
| right_knee | +104.07° | +78.23° | −25.83° |
| left_ankle | +49.54° | +35.90° | −13.64° |
| right_ankle | −50.16° | −35.70° | +14.46° |
| left_hip_pitch | +56.78° | +44.85° | −11.93° |
| right_hip_pitch | +57.95° | +46.55° | −11.40° |
| neck_pitch / head_pitch | 0° | +30° | +30° |

### 고친 것

`goto_ready.py` 를 다시 썼다.

* `TICK_RAD` / `CENTER` / ID / 부호 / 관절한계 / `tick_of` 를 전부
  `rustypot_hwi` 에서 **import** 한다. 자기 사본을 안 갖는다.
* READY 기본 출처가 `policy.meta.json` 이다. `--policy` 를 생략하면
  `~/policy*/` 중 메타가 가장 최근인 것을 자동으로 고르고 어느 것을 골랐는지
  찍는다. 하드코딩 값은 `--policy -` 로만 쓸 수 있고, 메타를 쓸 때도 그
  표와의 차이를 축별로 출력한다.

검산 (v46, `--dry-run`): left_knee −76.72° → 틱 1175
= 2048 − 1.3391/(2π/4096). 버그 상태에서는 1612 였다.

## 3.5. 실기 관절이 심보다 1.75 배 무르다 — P 게인 800 -> 1402

"정책이 명령한 위치에 실제 관절이 덜 간다" 는 관찰의 원인. 위치 게인을
실측하고 심과 **같은 단위로** 환산했다.

먼저 800/0/4700 이 어디서 왔는지부터. **아무도 쓰지 않았다.** 모드 전환 때
펌웨어가 넣는다 (2026-08-12 실측, left_knee, 토크 off):

| Operating Mode | P | I | D |
|---|---|---|---|
| 3 위치제어 | 800 | 0 | 0 |
| **5 전류기반 위치제어** (우리 모드) | **800** | **0** | **4700** |
| 4 확장위치제어 | 800 | 0 | 0 |

위치 PID 는 RAM 이라 전원 재인가·reboot **그리고 모드 전환** 때마다 되돌아
간다. 게인을 걸려면 `arm()` 이 모드를 쓴 **뒤** 여야 한다 — 순서를 뒤집으면
조용히 무효가 된다.

### 환산

모드 5 에서 위치 PID 의 출력은 곧 목표 전류다. e매뉴얼 환산 KPP = P/128.

    kp = (800/128) [전류단위/tick] × (1.96 × 2.69 mA) [N·m/전류단위]
                                   ÷ (2π/4096)        [rad/tick]
       = 6.25 × 5.272e-3 / 1.534e-3 = 21.5 N·m/rad

| | 관절강성 |
|---|---|
| 심 `stiffness` | **37.65 N·m/rad** |
| 실기 P=800 | **21.5 N·m/rad** (심의 57 %) |

같은 부하에서 실기 관절이 1.75 배 더 밀린다. 심의 값과 맞추는 P 는 **1402**.

### P 와 전류상한은 서로 다른 문제를 고친다

| P | 관절강성 | 심 대비 | 700 틱에서 포화하는 오차 |
|---|---|---|---|
| 800 | 21.5 | 57 % | 9.8° |
| 1200 | 32.2 | 86 % | 6.6° |
| **1402** | **37.65** | **100 %** | 5.6° |
| 2000 | 53.7 | 143 % | 3.9° |

토크 천장은 P 와 무관하게 1.96·(I−0.27) 이다. 그래서:

* **오차 < 6° (정상 추종)** — P 게인의 영역. 800→1402 로 복원토크 1.75 배.
* **오차 > 10° (무너질 때)** — 전류상한의 영역. 350→700 으로 천장 1.32→3.16 N·m.

둘 다 필요하다. `rl_walk.py` 기본값을 `--current 700 --pgain 1402` 로 했다.

### D 게인은 손대지 않았다

KPD = D/16 = 293.75 로 P 대비 47 배지만, 이걸 심의 `damping` (1.352 N·m·s/rad)
과 비교하려면 서보 내부 위치루프의 주기를 알아야 하는데 e매뉴얼에 없다.
근거 없이 바꾸지 않고 `--dgain` 으로 열어만 뒀다. 참고로 머리 3축은
2026-08-09 계단응답 실측으로 2000 이 최적이었다 (D=0 은 외란에서 크게 출렁).

### 검증

`--pgain` 쓰기 경로를 토크 off 상태에서 확인했다: 다리 10축 전부 1402 수용,
읽기 확인, 800 복귀. `rl_walk` 는 시작할 때 게인을 **다시 읽어서** 실제
값으로 강성을 찍고, 명령값과 다르면 경고한다 (모드 전환이 덮는 사고 방지).

## 4. 아직 못 푼 것 — 무릎 전류/PWM 이 말이 안 된다

마지막 v46 로그 (17 행, 0.36 초) 에서:

```
t=0.16  left_knee  목표 −60.0°  실제 −79.2°  오차 19.1°  PWM 1.000  전류 0.005 A  토크 ON
t=0.28  right_knee 목표 +80.2°  실제 +71.5°  오차  8.7°  PWM −0.391 전류 −1.014 A  토크 ON
```

Position P Gain 800 에서 오차 19° (218 틱) 면 PWM 이 포화되고 전류는 상한에
붙어야 한다. PWM 은 실제로 포화(±1.000)했는데 전류가 0.005 A 다.

> **아래 5절에서 풀렸다.** 전압이 8.7 V 로 무너져 있었다. 듀티를 100 % 로
> 밀어도 전압이 없으면 전류가 안 흐른다.

### 로그 열은 깨지지 않았다 (정정)

이 절에서 처음에 "`goal_*` / `pwm_*` / `err_*` 열이 −1/1/−2, 0 같은 값으로
깨져 있다" 고 적었는데 **틀렸다. 셋 다 멀쩡하다.**

* `goal_*` 은 tick 이 아니라 **rad** — `set_position_vec()` 이 URDF 클램프
  뒤 실제로 나간 각도를 rad 로 돌려준다.
* `err_*` 은 위치오차가 아니라 **하드웨어 에러 비트마스크** (0 = 정상).
* `pwm_*` 은 885 로 나눈 **정규화 듀티** (−1 ~ +1).

소수점 없이 출력해 놓고 읽어서 생긴 오독이다.

## 5. 진짜 원인 — 전원이 무너지고 있었다 (PD 어댑터)

위의 게인·전류상한 수정을 다 적용하고 (`--current 700 --pgain 1402`,
관절강성 37.65 = 심과 일치) v46 을 돌린 로그(426 행, 8.97 s, 47.5 Hz):

```
t = 0.0 ~ 2.0 s   전압 11.2 ~ 11.4 V
t = 2.0 s         급락
t = 2.0 ~ 9.0 s   전압  8.6 ~  9.1 V   (끝까지 회복 없음)
```

XM430 의 Min Voltage Limit 은 95 = **9.5 V**. 8.7 V 는 규격 밖이다.

전원은 **USB-PD 어댑터의 12 V 프로파일**이었다. PD 12 V 는 보통 3 A(36 W)
가 상한인데, 측정된 다리 10축 합계 전류가 순간 **5.22 A**, 평균 2.15 A
였다. 머리 4축까지 더하면 어댑터 용량을 넘는다. "11.3 V 유지 → 계단 하강
→ 무회복" 은 PD 소스가 과전류에서 접는 모양 그대로다. 부하를 빼면
11.6 V 로 **회복한다** — 배터리 방전이 아니라 공급 능력 부족이다.

무부하에서 이미 11.3 V 인 것도 신호였다 (12 V 어댑터인데 0.7 V 가
트리거 보드·케이블에서 떨어진다).

### 어디까지가 확정이고 어디부터가 추측인가

처음 이 절을 쓸 때 "이것이 그동안의 모든 증상을 설명한다" 고 적었는데
**과했다.** 갈라서 적는다.

**확정 (직접 측정):**

* 버스 전압이 8.7 V 까지 내려갔다. XM430 Min Voltage Limit 은 9.5 V 다.
  런 중 네 개 샘플에서 반복 확인했다.
* 무부하로 돌아오면 11.6 V 로 회복한다 → 방전이 아니라 부하 의존 새그.
* PD 12 V 프로파일은 통상 3 A / 36 W. 14축 보행 로봇이 그 안에 못 들어간다
  — 이건 로그와 무관하게 성립하는 용량 계산이다.

**확정 아님:**

* **언제 떨어졌는지 모른다.** 이 런은 `VOLT_PERIOD=100`(2.1 초) 이라 9 초
  동안 전압을 다섯 번밖에 안 읽었다. t≈0 에 11.2 V, 다음 샘플 t≈2.1 에
  이미 8.7 V 였을 뿐이다. "t=2.0 s 에 급락" 은 그 사이를 메운 추측이다.
  (그래서 25 스텝 = 0.5 초로 당겼다.)
* **넘어져서 전압이 떨어진 것인지, 전압이 떨어져서 넘어진 것인지** 이
  로그로는 못 가른다. 강하 구간 전후로 다리 합계 전류에 눈에 띄는 스파이크는
  없었지만 (1.5~3.3 A), 전류도 순간 샘플이라 근거가 약하다.
* **좌우 무릎 비대칭은 전압으로 설명되지 않는다.** 같은 레일인데 왼쪽만
  평균 오차 +22.9°, 오른쪽은 −2.0° 다. 전압이 떨어지기 전 구간(t<2.1 s)
  에도 왼쪽은 이미 +12.6° 였다.

**`pwm_*` 와 순간 `cur_*` 은 이 추론에 쓸 수 없다.** 왼무릎이 거의 정지
(|vel| < 0.5 rad/s, 275 샘플) 인데 PWM 포화에 전류 0.043 A 이고, 오른무릎도
같은 조건에서 0.164 A 다. 정지면 역기전력이 없으므로 8.7 V 가 ~2 Ω 권선에
걸리면 암페어 단위가 흘러야 한다. 둘 다 물리적으로 불가능하다. 게다가
오른무릎은 오차 −1.9° 로 **잘 따라가는데** 70 % 가 포화다 — 그 자체로
모순이다. 50 Hz 스냅샷이 서보 내부 고속 루프의 레일-투-레일 스윙을 찍고
있는 것으로 본다. 위치(`pos_`)와 목표(`goal_`), 그리고 전압만 믿는다.

### 그래도 전원부터 고치는 이유

인과가 확정돼서가 아니라, **규격 밖 전압에서는 나머지를 진단할 수 없어서**다.
지금 무릎을 파 봐야 "전압이 없어 못 움직인 것" 과 "무릎이 고장난 것" 이
구분되지 않는다. 전원은 용량 계산만으로도 독립적으로 부족이 증명되므로,
먼저 고치고 그 다음에 다시 재는 것이 유일하게 진행 가능한 순서다.

### 정정 두 가지

1. 2026-08-12 오전에 "전압 11.6~11.7 V 정상, InputVoltage 비트는 낡은
   래치" 라고 결론냈는데, 그건 **무부하 측정**이었다. 부하가 걸리면 무너진다.
2. 다만 `hw_error` 비트만으로는 판단할 수 없다. 그 비트는 한 번 뜨면
   reboot 전까지 **래치**돼서, 전압이 11.3 V 로 멀쩡한 구간에도 1 로 남아
   있었다. 실시간 증거는 비트가 아니라 **전압 열**이다.

### 고친 것

`rl_walk.py` 에 브라운아웃 가드. 전압 읽기 주기를 100 스텝(2 초) → 25
스텝(0.5 초) 으로 당기고, 10.0 V 아래가 2 회 연속이면 정지한다. 규격 밖
전압에서 나오는 로그는 아무것도 못 믿으므로 계속 돌릴 이유가 없다.
토크를 켜기 **전에** 무부하 전압도 찍고, 11.5 V 아래면 경고한다.

### 전원 요구사항

다리 10축이 700 틱(1.88 A) 상한이므로 이론상 최악 18.8 A, 머리까지 26 A.
실측 피크는 5.22 A 였지만 그건 2 초 만에 레일이 무너져 더 못 뽑은 값이라
**하한**으로 봐야 한다.

* **3S LiPo** (11.1 V 공칭, 만충 12.6 V) — XM430 최대 16 V 안에 들어간다.
* **4S 는 안 된다** (만충 16.8 V > 16 V 규격). 쓰려면 강압 필요.
* 유선을 유지하려면 12 V **10 A 이상** 벤치 파워 + 굵은 선.
* 서보가 보고하는 전압은 배선 강하까지 포함한 **서보 단자 전압**이라,
  `volt.py` 를 부하 중에 읽는 것이 올바른 계측이다. 소스 쪽 표시값이 아니라.

### 다음

전원을 고치기 전의 하드웨어 측정은 전부 다시 봐야 한다 — 주파수 응답,
full_check, 무릎 좌우 비대칭 모두 레일이 처진 상태에서 잰 것일 수 있다.
순서: **전원 교체 → volt.py 로 부하 중 전압 확인 → 그 다음에 나머지 재측정.**

## 6. 전원 교체 후 — 확정

2026-08-13. 전원을 바꾸고 v46 을 **다른 것은 하나도 안 바꾸고** 다시 돌렸다
(`--current 700 --pgain 1402`, 같은 onnx, 같은 메타).

| | 이전 (PD 어댑터) | 이후 (전원 교체) |
|---|---|---|
| 전압 최저 | 8.6 V | **11.2 V** |
| 다리 합계 전류 최대 | 5.22 A | **10.12 A** |
| 접지 전환 | 1.56 /s | **8.26 /s** |
| 왼무릎 평균오차 | **+22.9°** | **+2.7°** |
| 왼무릎 RMS | 26.2° | **9.3°** |
| 오른무릎 RMS | 8.2° | 8.4° |
| 왼무릎 평균전류 | 0.103 A | **0.726 A** |
| pitch 범위 | −33 ~ +34° | −0.4 ~ +16.9° |
| hw_error | 1 (InputVoltage) | **0** |

### 결론

* **전원이 원인이었다.** 한 변수만 바꿔서 얻은 결과다.
* **좌우 무릎 비대칭은 존재하지 않았다.** 왼쪽 RMS 9.3° vs 오른쪽 8.4° 로
  이제 대칭이다. "왼무릎이 기구적으로 고장났다" 가설은 기각한다 — 굶주린
  것이지 망가진 것이 아니었다. 벤치 시험(주파수 응답, full_check)이 왼무릎을
  두 번 무죄로 판정했던 것이 옳았고, 그걸 뒤집으려 한 쪽이 틀렸다.
* **5.22 A 는 로봇의 수요가 아니라 어댑터의 상한이었다.** 전원을 바꾸니 같은
  동작에서 10.12 A 를 뽑는다. 부하 쪽 계측만 보고 "이 정도면 충분하겠지" 라고
  판단하면 안 된다는 사례다.
* 전압이 12.1 V → 11.2 V 로 처지므로 10 A 에서 소스+배선 저항이 약 90 mΩ
  이다. 규격 안이지만 굵은 선으로 더 줄일 여지가 있다.
* 온도 31~34 °C. 700 틱(1.88 A) 상한은 발열 문제가 없다.

### 남은 것

* pitch 가 평균 +11° 로 앞으로 기운 채 걷는다 (범위 −0.4 ~ +16.9°).
  무너지지는 않지만 자세가 서 있지 않다.
* 이 런이 2.91 초에서 끝난 것은 **사용자가 Ctrl+C 를 눌렀기 때문**이다.
  로봇이 실제로 걷기 시작해서 놀라 멈췄다고 한다. 로그에 이상 신호가 하나도
  없었던 것(전압 11.5 V, hw_error 0, 온도 34 °C, 마지막 행도 양발 접지에
  pitch +10°)이 그래서였다. **이 프로젝트에서 실기가 자기 발로 걸은 첫 기록
  이다.** 다음은 더 길게 돌려 봐야 한다.
* 다음: **v42** (2044 iter, 보상 367 vs v46 293). READY 무릎이 −89.7° 로
  v46 보다 13° 깊어 무릎 부하가 크지만, 이제 토크가 나오므로 조건이 된다.
