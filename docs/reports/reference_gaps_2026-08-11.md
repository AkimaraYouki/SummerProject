# 레퍼런스 보행의 구멍 세 가지 (2026-08-11)

실기에서 좌우 다리가 다르게 움직이고 저속에서 제자리걸음을 하는 원인을 쫓다가,
**정책이 아니라 레퍼런스 보행 자체**에 문제가 있다는 걸 찾았다.
`scripts/diag/ref_symmetry.py` 로 언제든 다시 잴 수 있다.

## 1. 격자의 절반이 폴백이다

pkl 은 (dx, dy, dθ) 격자마다 다항식을 갖는데, 녹화는 그 절반뿐이다.

| 파일 | 녹화 / 격자 | 충전율 |
|---|---|---|
| `ref_g125.pkl` (v41 이 쓰는 것) | 119 / 216 | **55 %** |
| `ref_g125s.pkl` | 143 / 270 | **53 %** |

빠진 칸은 런타임에서 `nearest_coeffs` 로 **가장 가까운 녹화로 조용히 폴백**된다
(`poly_reference_motion.py`). 로그도 경고도 없다.

원인은 `auto_waddle.py` 5 단계의 속도 필터다. medium 프리셋에서 총속도가
`slow`(0.05) 이하이거나 `fast`(0.15) 초과인 녹화를 **지운다.** 그런데 스윕은
±0.222 m/s 까지 돈다 — 상단이 통째로 걸러진다.
(그 필터에는 "예전엔 조용히 안 걸렸다" 는 주석이 달려 있다. 고쳐진 뒤로는
걸리고 있고, 그 부작용이 지금 이것이다.)

## 2. 직진 슬라이스가 비어 있다 — 속도를 바꿔도 레퍼런스가 안 바뀐다

가장 많이 쓰는 구간인데:

```
직진 슬라이스 (dy≈0, dθ=0)
  녹화 있음:  dx = -0.148, -0.074, +0.074
  빠짐:       dx =  0.0,  +0.148, +0.222      <- 전부 최근접 폴백
```

계수를 직접 찍어 확인했다. dx = 0.0 / 0.074 / 0.148 / 0.222 의 무릎 계수가
**소수점까지 동일**하다. 즉 **전진 속도를 바꿔도 레퍼런스 보행이 그대로다.**

이것이 저속에서 발을 구르는 원인이다. vx=0.02 를 줘도 dx=+0.074 용 보행
(풀스윙, 주기 0.54 s 고정)을 그대로 실행하므로, 한 주기에 11 mm 만 가면서
다리는 최대로 든다 — 제자리걸음이다.

## 3. dy 격자에 0 이 없다 (일부 파일)

| 파일 | dy 격자 | vy=0 이 스냅되는 값 |
|---|---|---|
| `ref_g125.pkl` | −0.111, −0.037, +0.037, +0.111 | **−0.037** |
| `ref_g115.pkl` | 같음 | **−0.037** |
| `polynomial_coefficients.pkl` | 같음 | **−0.037** |
| `ref_h175_symyaw.pkl` | 같음 | **−0.037** |
| **`ref_g125s.pkl`** | −0.148, −0.074, **0.0**, +0.074, +0.148 | **0.000** ✓ |

즉 v41 을 포함한 대부분의 학습이 **직진 명령에 옆으로 새는 보행을 레퍼런스로**
쓰고 있었다. `ref_g125s` 만 이 문제가 없는데, 정작 학습에 쓴 적이 없다.

## 좌우 대칭 측정값

vx=+0.222, vy=0, dθ=0 기준 진폭 좌우차:

| 관절 | `ref_g125` | `ref_g125s` |
|---|---|---|
| hip_pitch | **+41.0 %** | +18.6 % |
| knee | +11.1 % | +16.5 % |
| ankle | −8.0 % | +7.6 % |
| hip_roll | −3.6 % | +0.1 % |

**placo 원본 녹화는 거의 대칭이다** — 원본 JSON 을 직접 재니 무릎 진폭 좌우차
+3.3 %, hip_pitch +7.7 % 였다. 즉 대칭을 깨는 것은 placo 가 아니라 **격자 폴백**
이다. 폴백된 칸은 좌우가 서로 다른 녹화를 가리키게 된다.

## 시도했다가 버린 것

적합된 pkl 을 사후에 대칭화하는 스크립트를 만들었다 —
`frame_sym(t) = ½(frame(t) + M[frame_mirror(t+T/2)])`. **버렸다.**
진폭이 748° 로 폭주했고, 근본적으로 틀린 접근이었다: 격자의 절반이 폴백이라
"거울 짝" 이 실제로는 같은 데이터를 가리키는 경우가 많아 평균이 무의미하다.
**격자를 제대로 채우는 것이 먼저다.**

## 다시 뽑을 때 고칠 것

1. **스윕 범위를 프리셋 속도대에 맞춘다.** medium(0.05~0.15)을 쓰면서 0.222 까지
   스윕하면 상단은 버려진다. `auto_gait.json` 의 `max_sweep_x` 를 0.04
   (= 0.148 m/s) 로 내리면 학습 명령 범위(vx ±0.15)를 정확히 덮으면서 필터에
   안 걸린다. 상단까지 살리려면 `fast` 프리셋을 따로 돌려 합쳐야 한다.
2. **dy·dθ 격자에 0 을 포함한다.** 현재 `auto_gait.json`(y ±0.04, 간격 0.02)은
   이미 0 을 포함한다 — `ref_g125` 는 옛 설정(±0.03, 간격 0.01)으로 만든 것이다.
3. **생성 후 충전율을 검증한다.** `scripts/diag/ref_symmetry.py` 로 재서 90 %
   미만이면 실패로 본다. 지금은 53~55 % 인데도 조용히 넘어갔다.
