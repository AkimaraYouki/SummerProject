## 원인 1 — 전류 상한이 정책이 기대하는 토크의 40 % 밖에 안 된다

`~/rustypot_hwi.py`:
```python
CURRENT_UNIT_MA = 2.69
def __init__(self, port="/dev/ttyUSB0", current_limit=350):
```
`~/rl_walk.py`: `ap.add_argument("--current", type=int, default=350, ...)`

```
350 unit × 2.69 mA = 941 mA
XM430-W350 : 스톨 4.1 N·m @ 2.3 A   (토크 ∝ 전류)
→ 실기에서 낼 수 있는 토크 ≈ 4.1 × 0.941 / 2.3 ≈ 1.68 N·m
```

학습한 심의 `effort_limit_sim` 은 **4.1 N·m** 이다. 심에서 이 정책의 보행 중
무릎 토크를 실측하면:

| 관절 (심, 보행) | RMS | 99 % | 최대 | 실기 천장 |
|---|---|---|---|---|
| left_knee | 1.229 | **3.393** | 4.100 (심 클램프) | **1.68** |
| right_knee | 1.193 | 3.032 | 4.100 | 1.68 |
| left_hip_roll | 1.039 | 2.934 | 4.100 | 1.68 |

평균은 천장 아래지만 **99 퍼센타일이 천장의 두 배**다. 정책이 의존하는 피크
토크를 실기가 못 낸다.

`rl_walk.py` 주석이 이미 예고하고 있었다:
> 전류 제한 (기본 350 unit = 0.94 A) — 다리가 실제 보행 부하를 못 버티고
> 멈추면(주저앉으면) `--current` 를 올릴 것. **이 값은 걷기용으로 검증된 적이 없다.**

그때는 기계적 간섭이나 감속비/링키지를 의심해야 한다. 보고만 하고 멈춘다.

## 원인 2 — 중력 관측이 생 가속도라 오염돼 있다

`~/rl_walk.py` 413 행 근처:
```python
accel_arr = np.array(accel, dtype=np.float32)
grav_norm = np.linalg.norm(accel_arr) or 1.0
projected_gravity = -accel_arr / grav_norm     # ← 생 가속도계를 정규화한 것
```

정책이 학습한 심의 `projected_gravity_b` 는 몸통 쿼터니언에서 뽑은 **참 중력 방향**
이라 잡음이 0 이다. 실기는 접지 충격 가속도가 그대로 섞인다:

| 측정 | 값 |
|---|---|
| accel 크기 평균 | 10.09 m/s² (중력만이면 9.81 고정이어야 함) |
| 9.81 에서 벗어난 정도 | 평균 1.63, 최대 **9.01** m/s² |
| 1 m/s² 넘게 벗어난 스텝 | **64.6 %** |
| 피치 인접샘플 변화 | 평균 7.0°, 최대 **35.1°** (20 ms 간격) |

2.7 kg 로봇이 20 ms 에 35° 를 기울일 수는 없다. **정책이 매 스텝 거짓 자세를
관측하고 있다.** 관측 107 차원 중 3 개가 쓰레기면 그 위에서 나오는 액션도 쓰레기다.

### 이미 칩 안에 정답이 있다

IMU 는 **BNO055** 이고 `~/rl_walk.py` 의 `Imu._wake()` 가 `MODE_NDOF (0x0C)` 로
설정한다 — 9축 센서 융합이 **이미 돌고 있다**. NDOF 모드에서 BNO055 는 융합 결과로
중력만 분리한 벡터를 `GRV_DATA (0x2E)` 에 내놓는다. 그런데 코드는 생 가속도인
`ACC_DATA (0x08)` 를 읽고 있다. **레지스터 주소 하나 문제다.**

BNO055 레지스터 (참고):
| 주소 | 내용 |
|---|---|
| 0x08 | ACC_DATA — 생 가속도 (중력 + 선형가속도) ← 지금 읽는 것 |
| 0x14 | GYR_DATA — 자이로 |
| 0x28 | LIA_DATA — 선형가속도만 (중력 제거) |
| **0x2E** | **GRV_DATA — 중력만 (선형가속도 제거)** ← 써야 할 것 |

`GRV_DATA` 의 LSB 스케일은 `ACC_DATA` 와 같다 (m/s² 단위 모드에서 100 LSB = 1 m/s²).
즉 `ACC_LSB = 100.0` 을 그대로 쓰면 된다.

### 할 일 2

`~/rl_walk.py` 를 다음과 같이 고친다.

**(a) 레지스터 상수 추가** — `REG_ACC_DATA = 0x08` 옆에:
```python
REG_GRV_DATA = 0x2E     # BNO055 NDOF 융합 중력벡터 (선형가속도 제거됨)
```

**(b) `Imu.read()` 가 중력벡터도 돌려주게 한다.** 현재:
```python
def read(self):
    """(gyro_trunk[rad/s], accel_trunk[m/s^2, 중력 포함]) — 몸통 프레임으로 리맵."""
    a = self._vec(REG_ACC_DATA, ACC_LSB)
    g = self._vec(REG_GYR_DATA, GYR_LSB)
    g = tuple(v * math.pi / 180.0 for v in g)
    m = self.axis_matrix
    a_t = tuple(sum(m[i][j] * a[j] for j in range(3)) for i in range(3))
    g_t = tuple(sum(m[i][j] * g[j] for j in range(3)) for i in range(3))
    ...
```
여기에 `grv = self._vec(REG_GRV_DATA, ACC_LSB)` 를 추가하고, **`axis_matrix` 를
가속도와 똑같이 적용해서** (같은 센서 좌표계다) 세 번째 값으로 함께 돌려준다.
생 가속도(`a_t`)는 로그에 계속 남겨야 하니 **지우지 말 것**.

**(c) `projected_gravity` 를 융합 출력으로 바꾼다.**
```python
grv_arr = np.array(grav_trunk, dtype=np.float32)
n = np.linalg.norm(grv_arr) or 1.0
projected_gravity = -grv_arr / n
```
부호 규약은 **기존과 똑같이 유지한다** (`-vec/|vec|`). 심의
`projected_gravity_b` 는 똑바로 섰을 때 `(0, 0, -1)` 이다. 로그 첫 줄에서
기존 코드가 `(0.0394, −0.0488, −0.9980)` 을 냈으니 규약은 맞다 —
**바꾸면 안 된다.**

**(d) CSV 로그에 열 3개를 추가한다**: `grav_x, grav_y, grav_z` (융합 원값).
기존 `accel_*` 와 `proj_grav_*` 열은 **그대로 두고 추가만** 한다. 그래야 이번
로그와 다음 로그를 같은 분석기로 비교할 수 있다.
