## 원인 1 — 전류 상한이 심의 토크 한계보다 2.4 배 낮다

`rustypot_hwi.py` 의 기본 `current_limit=350`, `CURRENT_UNIT_MA=2.69`:

```
350 × 2.69 mA = 941 mA
XM430-W350 : 스톨 4.1 N·m @ 2.3 A  (토크 ∝ 전류)
사용 가능 토크 ≈ 4.1 × 0.941 / 2.3 ≈ 1.68 N·m
```

심의 `effort_limit_sim = 4.1` 이다. **심은 실기가 낼 수 없는 토크를 2.4 배 허용한
채로 학습했다.** `scripts/diag/torque_load.py` 로 잰 v40 보행 중 무릎 토크와 나란히
놓으면:

| | RMS | 99% | 최대 | 실기 천장 |
|---|---|---|---|---|
| left_knee (심, 보행) | 1.229 | **3.393** | 4.100 (= 심 클램프) | **1.68** |
| right_knee | 1.193 | 3.032 | 4.100 | 1.68 |
| left_hip_roll | 1.039 | 2.934 | 4.100 | 1.68 |

평균(RMS)은 천장 아래지만 **99 퍼센타일이 천장의 두 배**다. 즉 정책이 의존하는
피크 토크를 실기가 못 낸다. 무릎이 못 펴진 것과 정확히 일치한다.

`rl_walk.py` 주석 자체가 이걸 예고하고 있었다:
> 전류 제한 (기본 350 unit = 0.94 A) — 다리가 실제 보행 부하를 못 버티고
> 멈추면(주저앉으면) `--current` 를 올릴 것. **이 값은 걷기용으로 검증된 적이 없다.**

## 원인 2 — 중력 관측이 생 가속도라 오염돼 있다

`rl_walk.py:413`:
```python
projected_gravity = -accel_arr / grav_norm      # 생 가속도계를 정규화한 것
```

심의 `projected_gravity_b` 는 몸통 쿼터니언에서 뽑은 **참값**이라 잡음이 없다.
실기는 접지 충격 가속도가 그대로 섞인다:

| | 값 |
|---|---|
| accel 크기 평균 | 10.09 m/s² (중력만이면 9.81 고정) |
| 9.81 에서 벗어난 정도 | 평균 1.63, 최대 **9.01** m/s² |
| 1 m/s² 초과한 스텝 | **64.6 %** |
| 피치 인접샘플 변화 | 평균 7.0°, 최대 **35.1°** (20 ms 간격) |

2.7 kg 로봇이 20 ms 에 35° 를 기울일 수는 없다. **정책이 매 스텝 거짓 자세를 받고
있다.** 관측 107 차원 중 3 개가 쓰레기면 그 위에서 나오는 액션도 쓰레기다.

**그런데 고칠 신호가 이미 칩 안에 있다.** IMU 는 BNO055 이고 `MODE_NDOF (0x0C)`,
즉 9축 융합이 이미 돌고 있다. NDOF 모드는 융합 결과로 중력만 분리한 벡터를
`GRV_DATA (0x2E)` 에 내놓는데, 코드는 생 가속도인 `ACC_DATA (0x08)` 를 읽고 있다.
**레지스터 주소 하나 문제다.**

## 부수 관측

* 제어 주기 평균 21.0 ms (47.6 Hz), 중앙 20.0, **최대 76.2 ms**, 20 ms 초과 58.9 %.
  76 ms 는 제어 스텝 3.8 개를 건너뛴 것. 주된 원인은 아니지만 여유를 깎는다.
* 넘어진 뒤 `left_hip_roll` 목표가 한계 +25° 를 10° 넘겼다. 넘어진 뒤의
  분포 밖 구간이라 원인이 아니라 결과로 본다.
* 좌우 대칭이 실기에서 무릎 −21.97°, hip_pitch −14.50° 로 무너졌다.
  심에서는 v40 이 0.40°/0.54° 였다. 이것도 넘어진 결과지 원인이 아니다.

## 다음

**A. 전류 상한 올리기 (재학습 불필요, 즉시).** 350 → 700 unit (1.88 A ≈ 3.35 N·m).
   XM430 은 스톨 전류를 지속하면 과열되므로 온도를 보면서 짧게 시험할 것.
   매달아 놓고 먼저 볼 것.

**B. 중력 관측을 융합 출력으로 (재학습 불필요, 한 줄).**
   `REG_ACC_DATA(0x08)` → `REG_GRV_DATA(0x2E)`. 칩이 이미 계산해 두고 있다.

**C. 심의 토크 한계를 실기에 맞추기 (재학습).** `effort_limit_sim` 4.1 → 실기
   천장. 사용자가 목표 1 에 넣은 "모터부하" 가 바로 이것이고, A 로 천장을 올리든
   말든 **심이 실기보다 후한 상태로는 sim2real 이 계속 깨진다.**

A·B 는 되돌리기 쉽고 재학습이 필요 없으니 먼저 확인하고, 그 결과를 보고 C 의
목표 토크를 정하는 순서가 맞다.
